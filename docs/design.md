# Edaori 設計書 — AIチャットの分岐ナビ

## 課題と目的

AIチャットは会話が一本道のスクロールで進みます。そのため、途中で出た選択肢や並行して考えていたことが流れて消え、分岐点に戻れないまま中途半端に終わりがちです。Edaori は会話を「枝分かれする作業ツリー」として並べ、今どこにいて、何が残っているかを常に見えるようにします。

解決したい4つのこと：

1. **全体を見渡せる**：どこで枝分かれし、どの枝がまだ続いているかを一目で見る
2. **分岐点に戻れる**：戻った瞬間に、その時点の文脈をAIに渡し直せる
3. **未完了が見える**：保留・放置中の枝が一覧に残り、忘れない
4. **次にやることが分かる**：1つ片付くと「次はこの枝」と提案される

チャットアプリ自体は作りません。既存のAI（Claude / GitHub Copilot / Cursor）の横に置く「ナビ」に徹します。

## コンセプトと基本モデル

git の考え方をそのまま会話に当てはめます。要点は「枝を切るときに戻り道を保存し、枝を閉じるときに結論を親に持ち帰る」ことです。

| git | Edaori での意味 | コマンド |
| --- | --- | --- |
| commit | 枝の上で進んだ論点や進捗のメモ | `note` |
| branch | 選択肢・並行検討・脱線が発生した | `fork` |
| HEAD | 今話している枝 | — |
| checkout | 分岐点や別の枝に戻る（復帰パックで文脈を渡し直す） | `resume` |
| stash | 一時停止。止めた理由と止めた位置を残す | `park` |
| merge | 結論を1行にまとめ、親の分岐点へ集める | `done` |
| — | 選択肢を捨てる。捨てた理由を残す | `reject` |

枝の状態は **未着手 ○ / 進行中 ▶ / 保留 ‖ / 完了 ✓ / 却下 ×** の5つだけです。分岐点は ◆ で表します。「却下」を残しておくのが大事で、捨てた選択肢とその理由を後から読み返せます。

## 基本ループ

```
 会話する(HEAD) ──▶ 枝分かれした？ ──はい──▶ fork: 枝を並べる ──▶ 1つ選んで進む
      ▲                                                          │
      │ 再開プロンプト                          途中で止める ◀────┤────▶ やり切った
      │                                             ▼                    ▼
 resume(復帰パック) ◀── NEXT: 次の枝を提案 ◀── park(止めた位置)    done(結論1行 → 親へ)
                                ▲                                         │
                                └─────────────────────────────────────────┘
```

枝は必ず「完了」か「保留」（または「却下」）で閉じます。閉じた瞬間に HEAD は親の分岐点に戻り、NEXT が表示されます。そのため「どこに戻るんだっけ」が起きません。

### NEXT の選び方（上から順に候補を探す）

1. ★ピン留めした枝
2. HEAD から近い順に、未着手の枝と「再開OK」にした保留の枝（今の枝の中 → 同じ分岐点の残り → さらに上の分岐点の残り）
3. 子の枝が全部閉じた分岐点 → 「まとめて done にする」を提案
4. 残りが保留の枝だけなら、その件数と「再開条件を満たしたら `ready`」を案内

## 記憶の復元（戻ったときに文脈が残っているか）

AIの記憶は当てにしない前提です。分岐した瞬間に、AI自身に「その時点の記憶」を書き出させて保存し、戻るときに組み立て直します。

1. **分岐時にスナップショットを取る**：`fork` にはスナップショットを付けます。中身は目的・前提・決定済み・選択肢・未解決の問い・原文の抜粋2〜3個で、500〜800字が目安です。書くのは、その瞬間に文脈を全部持っているAIです。
2. **保留時に止めた位置を残す**：「どこまでやった・次に何をする予定だった」を必須にします（`--stopped-at`）。
3. **戻るときに組み立てる**：`resume` は次の3つを返します。遠い祖先の分岐点は結論だけに圧縮します。
   - ① 分岐時点の記憶（当時）
   - ② この枝のメモと止めた位置
   - ③ その後、ほかの枝で分かった結論（最新）
4. **復唱で確認する**：再開前にAIが「目的・前提・次の一手」を3行で言い、ユーザーが確認します。
5. **本物の巻き戻しも使う**：Claude Code の `/rewind` などで元の会話に戻れる場合はそれを使い、③だけを補います。

## 実施レポート（wrap-up）

すべての操作は `events`（追記のみのログ）に残ります。チャットを締めるときは、そこから次の内容をまとめて出力します。

- ✓ 実施したこと（時系列・使ったツール付き）
- ◆ 決めたこと・却下した理由
- ‖ 保留中（止めた位置・再開条件）
- ○ 未着手
- → 次にやること

スキルの手順では、AIが会話全体とログを見比べて「記録漏れの候補」を示し、ユーザーが承認したものだけを追加してからレポートを出します。

## 画面（ナビ）

```
┌─ NOW 今いる枝 ────────┬─ NEXT 次にやること ───┐  ┌─ 復帰カード ─────────┐
│ 台本をどう作る？ ◆     │ テンプレ台本 ○         │  │ 分岐元 / 止めた位置    │
└───────────────────┴──────────────────┘  │ 再開プロンプト [コピー]│
┌─ グラフ（縦の gitgraph 風）────────────────┐  ├─ 未完了 (n) ──────────┤
│ ●─┬─◆ 何を売る？                            │  │ ‖ B. テンプレ販売       │
│   │  ├─● A ✓  ├─● B ‖  └─● C ×            │  │ ○ テンプレ台本          │
│   └─● 動画の作り方 ─◎ 台本 ◆ ← HEAD          │  └──────────────────┘
└─────────────────────────────────────┘
```

- `edaori.py view` でローカルサーバーが立ち上がり、2秒ごとに自動で更新します
- マインドマップ表示への切り替えは MVP の後に追加します。同じデータを2通りに描き分けるだけです

## データ構造

```json
{
  "version": 1,
  "session": { "id": "demo", "title": "副業の方向性を決める",
               "head": "n_004", "next": "n_005", "seq": 5,
               "createdAt": "...", "updatedAt": "..." },
  "nodes": [
    { "id": "n_004", "parentId": "n_002", "type": "branch",
      "title": "B. テンプレ販売", "status": "parked",
      "notes": ["Notion案を3つ出した"], "conclusion": null,
      "parkReason": "Aの反応を見てから", "stoppedAt": "案3つまで。次は価格",
      "resumeWhen": "Aの結論が出たら", "resumeReady": false, "pinned": false,
      "snapshot": null, "source": { "tool": "claude" },
      "createdAt": "...", "updatedAt": "..." }
  ],
  "events": [ { "t": "...", "op": "park", "node": "n_004", "text": "...", "tool": "claude" } ]
}
```

- `type` は `topic`（テーマの根）/ `fork`（分岐点）/ `branch`（枝）のいずれかです
- 再開プロンプトは保存しません。毎回、最新の記録から組み立てます

## AI連携

| レベル | 誰が書くか | 仕組み | 状況 |
| --- | --- | --- | --- |
| Lv0 | AIが回答の末尾に書く | カスタム指示で毎回ツリーを出させる | すぐ使える |
| Lv1 | 自分 | ナビ画面・CLIを手で操作する | 実装済み |
| **Lv2.5** | **AIがスキル経由で実行** | **Agent Skills（SKILL.md）＋ `edaori.py`** | **実装済み（本命）** |
| Lv3 | AIがツールを呼ぶ | MCPサーバー（`edaori.py` を包むだけ） | ファイルに書けない Claude アプリ向けに今後作る |

Claude Code・VS Code Copilot・Cursor はどれも共通規格の Agent Skills に対応しているため、スキルは1つで済みます。ChatGPT などは対象外です。そのため、ブラウザ拡張は当面作りません。

## 決定事項

- **対象AI**：Claude / GitHub Copilot（VS Code）/ Cursor
- **セッションはテーマ単位**：1つのテーマに、複数のチャットや複数のツールでの作業をまとめる
- **保存先はテーマごとに選べる**：リポジトリ内（`.edaori/`）か共通フォルダ（`~/.edaori/`）。どちらに置いても `~/.edaori/index.json` の台帳に登録される
- **チームでは共有しない（個人用）**：`.edaori/` は `.git/info/exclude` に自動で登録し、`.gitignore` は変更しない
- **グラフ表示**：縦の gitgraph 風とマインドマップを切り替えられるようにする（MVP は縦のみ）
- **将来の統合**：画面オーバーレイ型のAIアシスタントに統合する。そのため、作りを「データ（branches.json）／コア（edaori.py）／表示」の3層に分け、表示だけを差し替えられるようにする

## リスク

| リスク | 対策 |
| --- | --- |
| 記録が面倒で使われなくなる | 入力は1行まで。必須は「完了の結論」と「保留の止めた位置」だけ。スキルで自動化する |
| AIの分岐判定がずれる | AIは提案、確定はユーザー。正本は branches.json |
| 枝が細かくなりすぎる | 「あとで戻りたくなるものだけ枝にする」。小さなことは `note` で済ませる |
| 戻ってもAIが文脈を覚えていない | 復帰パックと復唱チェックで補う。別のチャットで再開しても成立する |
| スキルが自動で呼ばれない | 手動の `/edaori` や「分岐して記録して」を併用する |
